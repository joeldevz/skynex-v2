# Skynex 0.4.0 — notas del candidato local

Estado: preparación local; no publicado. Estas notas no autorizan crear una etiqueta,
subir cambios, publicar en npm ni actualizar instalaciones globales.

## Novedades

- CLI: `skynex task recovery record` y `skynex task recovery history` para registrar
  y consultar recuperación con revisiones optimistas, entradas acotadas y validación
  semántica del historial. La ayuda enumera ambos comandos.
- Tasks: historial de recuperación optativo en el esquema 3. Los esquemas 1 y 2
  siguen admitidos; registrar recuperación puede promover una tarea al esquema 3.
- Thalam: clasificación local sin el clasificador externo; trabajo directo como
  ruta predeterminada, TDD por petición explícita o por la ruta de alto riesgo
  definida en el agente. No usar TDD no elimina las pruebas existentes.
- Procedimientos de recuperación y validación en las skills bajo demanda
  `thalam-recovery` y `thalam-validation`.
- Menos llamadas de preparación: lecturas independientes agrupadas, delegación con
  motivo concreto y comprobación previa de cambios locales antes de editar.
- Cierre del trabajo con las pruebas existentes del módulo sobre el estado final;
  no basta un test nuevo o lint en verde si hay regresiones pendientes.
- Neurox: descubrimiento de herramientas diferidas antes de invocarlas, nombres y
  firmas obtenidos del catálogo, corrección de nombres acotada y guardado explícito
  de hallazgos reutilizables con archivos de entrada y comando de verificación.
- Runtime: namespace de memoria por repositorio para las llamadas de proyecto,
  también en Code Mode, sin usar la memoria como estado operativo ni autorización.
- Recuperación: presupuestos por problema y solicitud, diagnóstico de solo lectura,
  preservación de cambios parciales y reconciliación de procesos antes de terminar.

## Seguridad y controles

Los cambios sensibles conservan dos revisores independientes sobre el mismo
candidato, salvo desactivación explícita por el usuario. Los avisos no son errores;
un error o una revisión incompleta no equivale a aprobación. Los controles de
recuperación del agente son instrucciones y registros, no un ejecutor autónomo ni
una garantía de cumplimiento del modelo.

## Compatibilidad y actualización

- Se mantiene el requisito de Node.js 24 o posterior.
- Actualizar la CLI antes de usar las skills que exigen `task recovery`.
- Las CLI antiguas pueden rechazar tareas con esquema 3; no forzar una escritura
  ni degradar el archivo manualmente. Conservar respaldo antes de actualizar.
- Los números de versión internos de los paquetes privados y del catálogo de
  recursos son independientes de la versión pública 0.4.0 y no se incrementan aquí.
- Las instalaciones locales anteriores realizadas como overlays pueden aparecer
  como modificaciones locales al ejecutar una actualización. Revisar las colisiones
  y conservar los cambios propios; no sobrescribirlos indiscriminadamente.
- Esta preparación no altera la CLI global ni los recursos globales instalados.

## Verificación y límites conocidos

La evidencia de este candidato se registra en la tarea
`preparar-release-local-0-4-0-sin-publicar`; las comprobaciones de versiones previas
no sustituyen ejecutar las del paquete 0.4.0.

El candidato local supera compilación, comprobación TypeScript, instalador,
recursos, recuperación del agente, Tasks, recuperación registrada, coordinación,
namespace, contrato npm y contrato del workflow de release. El tarball se ha
verificado y la CLI empaquetada supera una prueba aislada de `record/history`.
Estas comprobaciones locales no sustituyen una ejecución remota de GitHub Actions
ni una instalación de actualización de extremo a extremo desde cada versión previa.

- El verificador de OpenCode se actualiza para comprobar el enrutamiento vigente
  a la skill de Tasks, en lugar de exigir un encabezado retirado. La ejecución
  aislada pasa con los tres plugins de Skynex activos.
- La previsualización de un perfil existente se comprueba por RPC: devuelve el plan
  esperado y no modifica la configuración. Se comprueba por separado el rechazo de
  un perfil inexistente. El HTTP 500 observado anteriormente procedía de esa petición
  deliberadamente inválida, no de la prueba de un perfil válido.
- La comprobación estática del plugin TUI no acredita el renderizado interactivo.
- Los experimentos anteriores son comparaciones históricas sobre pocas cadenas;
  no prueban superioridad general ni fiabilidad absoluta de la memoria. La última
  corrección del descubrimiento no se ha sometido aquí a otro benchmark.
- Los reintentos del intermediario experimental de benchmarks quedan fuera del
  producto distribuido: no se promete reintento automático del proveedor en Skynex.

## Alcance de publicación

El paquete público incluye la CLI y los recursos declarados en su manifiesto, no
los resultados de benchmarks, respaldos, tareas privadas, notas de investigación ni
archivos de trabajo ajenos. La preparación del paquete no implica que el árbol Git
esté limpio o que los cambios pendientes estén ya separados en commits.
