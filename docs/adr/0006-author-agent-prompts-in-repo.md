# ADR 0006 — Author agent prompts in the repository

## Status

Accepted (2026-09-26).

## Context

Agent prompts under `targets/opencode/resources/canonical/agents/` were generated by
`scripts/import-real-resources.mjs` from a controlled snapshot of the global agent
sources. The snapshot is recorded in the private inventory
`.skynex/tasks/real-resources/global-inventory.json`, pinned by both the importer and
`docs/real-resources-execution-plan.md` to `e77b256d…`.

The recorded source for the orchestrator prompt, `agents/skynex-orchestrator.md`
(sha256 `eb46ce33…`), is not authoritative for this repository:

- The canonical file has already diverged from it. The agent was renamed to Thalam and
  its coordination contract was rewritten, so a re-import would overwrite authored work.
- A full re-import cannot currently complete anyway: several recorded source digests no
  longer resolve on this host, so a `--write` run fails before producing output.

The snapshot therefore exists but is stale, not missing. Treating it as the source of
truth would silently revert the repository.

## Decision

Treat `targets/opencode/resources/canonical/agents/**` as the authoring source of truth
for agent prompts. Editing them directly is correct and expected; they are not
regenerated from the historical snapshot.

`provenance.json` keeps the historical `source: "agents/skynex-orchestrator.md"` value
that `scripts/verify-real-resources.mjs` asserts, and its `generatedSha256` is updated
whenever a canonical agent changes. The pinned inventory remains a record of what was
imported, not a promise that the import is reproducible.

## Consequences

- A canonical agent edit must update the matching `generatedSha256` in
  `provenance.json`; `pnpm verify:real-resources` fails otherwise. That digest is a
  change detector, not an authenticity attestation: it is regenerated by the same edit.
- `source` and `sourceSha256` in `provenance.json` are historical references. Neither
  `pnpm verify:real-resources` nor CI resolves them, so they must not be read as a live
  guarantee that a reproducible source exists.
- Re-running `scripts/import-real-resources.mjs --write` against the historical snapshot
  would overwrite authored prompts and is prohibited. The importer still accepts
  `--write`; that prohibition is policy today, not an enforced control.
- Restoring import governance requires a new, committed snapshot plus a new inventory
  digest and pin, and an explicit review of the resulting diff.
